# Архитектура проекта PHP Functions Universe

## Общая архитектура
Проект использует уникальную архитектуру ленивой загрузки функций, реализованную через абстрактный класс `LazyMethodAbstract`. Это позволяет загружать функции только при их фактическом использовании, что экономит память и ускоряет выполнение кода.

## Ключевые компоненты

### LazyMethodAbstract
Абстрактный класс, реализующий основную логику ленивой загрузки:
- Статический метод `__callStatic` для перехвата вызовов несуществующих методов
- Метод `init` для загрузки функций из файлов
- Статический метод `__asClosure` для получения функций в виде замыканий
- Хранение информации о загруженных функциях в статическом массиве `$map`
- Защита от повторной загрузки уже загруженных функций
- Поддержка алиасов функций через константу `ALIAS`

### Классы-наследники
Классы в корне директории `src/` (Arr, Str, Integer и т.д.) наследуются от `LazyMethodAbstract` и определяют:
- Константу `NAME` - имя директории с функциями
- Константу `IDX` - индекс для идентификации класса в системе

### Файлы функций
Функции организованы в директории `src/Method/` по категориям:
- Каждая функция находится в отдельном PHP-файле
- Имя файла соответствует имени функции
- Функции объявляются в соответствующем пространстве имен

## Пути исходного кода
- `src/LazyMethodAbstract.php` - основная логика ленивой загрузки
- `src/{ClassName}.php` - классы-наследники для каждой категории функций
- `src/Method/{Category}/{function_name}.php` - файлы с отдельными функциями
- `src/MethodMin/{Category}/{function_name}.php` - минифицированные версии функций

## Паттерны проектирования
- Паттерн "Ленивая инициализация" - функции загружаются только при первом вызове
- Псевдо-автозагрузка функций - по аналогии с автозагрузкой классов
- Статическая фабрика - через статические методы классов
- Прокси-паттерн - через метод `__callStatic`

## Отношения компонентов
Классы-наследники используют `LazyMethodAbstract` как базу для реализации логики вызова функций. При вызове метода класса (например, `Arr::first()`), срабатывает `__callStatic`, который инициирует загрузку соответствующей функции из файла в директории `src/Method/Arr/`.

## Критические пути реализации
1. Вызов статического метода класса-наследника
2. Перехват вызова через `__callStatic`
3. Инициализация функции через `init`
4. Загрузка файла функции
5. Вызов загруженной функции

## Особенности реализации
- Использование `require` для загрузки файлов функций
- Проверка существования функции через `function_exists`
- Поддержка получения функций в виде замыканий для передачи по ссылке
- Использование минифицированных версий функций из `src/MethodMin/`

## Структура проекта
- `src/` - основной исходный код
- `src/Method/` - файлы с отдельными функциями
- `src/MethodMin/` - минифицированные версии функций
- `tests/` - тесты
- `build/` - скрипты сборки
- `bench/` - бенчмарки

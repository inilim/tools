# PHP Functions Universe - Краткое описание проекта

## Основная концепция
PHP Functions Universe - это библиотека, которая собирает все возможные PHP-функции в одном месте с системой ленивой загрузки. Больше не нужно подключать десятки отдельных файлов или тяжелые классы - функции загружаются только когда они действительно нужны.

## Архитектура
Проект использует уникальную систему ленивой загрузки функций, реализованную через абстрактный класс `LazyMethodAbstract`. Функции загружаются только при первом вызове, без лишней загрузки неиспользуемого кода. Работает по принципу `autoload`, но для функций.

## Структура
Проект состоит из множества классов, каждый из которых представляет собой группу функций по функциональному признаку:
- `Arr` - функции для работы с массивами
- `Str` - функции для работы со строками
- `Integer`, `Num` - функции для работы с числами
- `File`, `Path`, `FS` - функции для работы с файловой системой
- `Json`, `Xml` - функции для работы с данными форматов
- `Time` - функции для работы со временем
- `Obj` - функции для работы с объектами
- `Assert`, `Check` - функции для проверок и утверждений
- `Exp` - экспериментальные функции
- `Enum` - функции для работы с перечислениями
- `Sql`, `Zip`, `Refl` - специализированные функции
- `Lar`, `LarArr`, `LarStr`, `LarExp` - функции из фреймворка Laravel
- `PF` - полифилы для новых PHP функций
- `VD` - функции дампа/отладки
- `Other` - прочие вспомогательные функции

## Основные преимущества
1. **Полная независимость** - нет зависимостей, работает на чистом PHP
2. **Совместимость с любыми проектами** - от старых до современных
3. **Не требует Composer** (хотя поддерживает его)
4. **Ленивая загрузка** - функции загружаются только при первом вызове
5. **Экономия памяти** - меньше потребления RAM по сравнению с static-классами
6. **Оптимизированный код** - все функции минифицированы

## Правила нейминга функций
У функций есть префиксы, например "_v2", "_m2"
"_v2" - отвечает за обновленную версию, прошлая версия будет depracate. Версий может быть много.
"_m2" - отвечает за альтернативную стратегию выполнения. Стратегий может быть много.
Пример с "_v2":
```php
/**
 * @deprecated use lines_v2()
 * Get the contents of a file one line at a time.
 * @return \Closure():\Generator<string>
 * @throws \InvalidArgumentException
 */
function lines(string $pathToFile): \Closure
{
    \Inilim\Tool\Method\Assert\file($pathToFile);

    return static function () use ($pathToFile): \Generator {
        $file = new \SplFileObject($pathToFile);
        $file->setFlags(\SplFileObject::DROP_NEW_LINE);
        while (! $file->eof()) {
            yield $file->fgets();
        }
    };
}
```
```php
/**
 * Get the contents of a file one line at a time.
 * @return \Generator<int,string>
 * @throws \InvalidArgumentException
 */
function lines_v2(string $pathToFile): \Generator
{
    \Inilim\Tool\Method\Assert\file($pathToFile);
    $file = new \SplFileObject($pathToFile);
    $file->setFlags(\SplFileObject::DROP_NEW_LINE);
    while (! $file->eof()) {
        yield $file->fgets();
    }
}
```

Функции с префиксом "_m2", "_m3" как правило может внешне не отличатся, но внутрянка может радикально отличатся. Яркий пример это если фукнция потребляет много ОЗУ но скорость большая. Или наоборот ОЗУ минимальное потребление но скорость уменьшается.

## Текущее состояние проекта
Проект включает в себя более 30 классов-категорий функций, каждый из которых наследуется от LazyMethodAbstract. Архитектура позволяет эффективно использовать функции с ленивой загрузкой, что экономит память и ускоряет выполнение кода. Проект поддерживает различные версии PHP (от 7.4 и выше) и не имеет внешних зависимостей для основной функциональности.
